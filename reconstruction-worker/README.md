# DRIFT reconstruction worker

This is the real heavy-compute boundary for the public reconstruction queue. It processes the queued capture itself; it does not synthesize geometry, detections, or success. A completed job means that OpenDroneMap produced validated artifacts, while metric accuracy remains `review_required` until independent checkpoints or GCPs are supplied.

## Requirements

The host must provide Linux, Docker Engine with permission to use `/var/run/docker.sock`, FFmpeg/FFprobe, outbound HTTPS access, and enough CPU, RAM, disk, and time for the capture. The DRIFT backend must use the same PostgreSQL database as the worker and must be able to read the same artifact directory. The current sandbox does not have Docker or PostgreSQL installed, so a real ODM run cannot be claimed here.

## Reproducible local setup

From the repository root:

```bash
mkdir -p data/reconstruction data/reconstruction-work
cp reconstruction-worker/.env.example reconstruction-worker/.env
# Edit RECONSTRUCTION_ARTIFACT_HOST_ROOT in reconstruction-worker/.env
# to an absolute path, for example:
# RECONSTRUCTION_ARTIFACT_HOST_ROOT=/home/ubuntu/DRIFT-AI-ML-Platform/data/reconstruction
# RECONSTRUCTION_WORK_HOST_ROOT=/home/ubuntu/DRIFT-AI-ML-Platform/data/reconstruction-work

reconstruction-worker/preflight.sh

docker compose --env-file reconstruction-worker/.env \
  -f reconstruction-worker/docker-compose.yml up --build -d
```

The Compose stack starts PostgreSQL and the worker. PostgreSQL is exposed on port `5432` by default and persists in the `drift-postgres-data` volume. The worker polls `reconstruction_jobs` every ten seconds, uses the Docker socket to start `opendronemap/odm:latest`, and publishes files under the shared `RECONSTRUCTION_ARTIFACT_HOST_ROOT/<jobKey>/` directory. ODM is given the host-visible project path under `RECONSTRUCTION_WORK_HOST_ROOT`; this is required because the Docker daemon resolves `-v` source paths on the host, not inside the worker container. The application server must be started separately with the same database connection and with `RECONSTRUCTION_ARTIFACT_ROOT` set to that host directory so `/api/reconstruction/:jobKey/artifacts/:fileName` can serve the published files.

For the host-side backend, use:

```bash
export DATABASE_URL='postgresql://drift:drift@localhost:5432/drift'
export RECONSTRUCTION_ARTIFACT_ROOT="$PWD/data/reconstruction"
pnpm install
pnpm db:push
pnpm dev
```

`pnpm db:push` must complete before a job is queued so the `reconstruction_jobs` table exists. The backend's source upload must resolve to a real HTTPS URL reachable from the worker container. A localhost URL generated by the browser is not sufficient; use the configured object-storage URL or a host-accessible HTTPS origin.

## Windows host

The commands above are Bash commands and must not be run from `C:\Users\HP` in PowerShell. The `/home/ubuntu/...` path is a Linux sandbox path, not a Windows path. On Windows, install Docker Desktop with **Use the WSL 2 based engine** enabled, install Ubuntu from the Microsoft Store, and run the Linux commands inside the Ubuntu/WSL terminal. Docker Desktop must have WSL integration enabled for that Ubuntu distribution.

From Ubuntu/WSL, clone the repository into the Linux filesystem and run:

```bash
cd ~
git clone https://github.com/RidhimaKulashriz/DRIFT-AI-ML-Platform.git
cd DRIFT-AI-ML-Platform
mkdir -p data/reconstruction data/reconstruction-work
cp reconstruction-worker/.env.example reconstruction-worker/.env
sed -i "s#^RECONSTRUCTION_ARTIFACT_HOST_ROOT=.*#RECONSTRUCTION_ARTIFACT_HOST_ROOT=$PWD/data/reconstruction#" reconstruction-worker/.env
sed -i "s#^RECONSTRUCTION_WORK_HOST_ROOT=.*#RECONSTRUCTION_WORK_HOST_ROOT=$PWD/data/reconstruction-work#" reconstruction-worker/.env
reconstruction-worker/preflight.sh
docker compose --env-file reconstruction-worker/.env -f reconstruction-worker/docker-compose.yml up --build -d
```

If using PowerShell only for the repository preparation, the equivalent syntax is:

```powershell
git clone https://github.com/RidhimaKulashriz/DRIFT-AI-ML-Platform.git
Set-Location .\DRIFT-AI-ML-Platform
New-Item -ItemType Directory -Force .\data\reconstruction
Copy-Item .\reconstruction-worker\.env.example .\reconstruction-worker\.env
```

Then open the Ubuntu/WSL terminal, `cd` to the cloned repository, and run the Bash commands. PowerShell uses backticks for line continuation, not `\`; `preflight.sh` is a Bash script and is not directly executable by native PowerShell. Keep the repository under the WSL Linux filesystem, such as `~/DRIFT-AI-ML-Platform`, for better Docker and file-watching performance.

## Real acceptance path

1. Upload one real drone video through the existing `reconstruction.uploadSource` flow. The current endpoint enforces a 50 MB limit and stores the original bytes through the configured storage provider.
2. Pass the returned HTTPS `sourceUrl`, exact file name, MIME type, byte size, real location, and capture metadata to `reconstruction.create`.
3. Confirm the returned job is `queued`, then follow `reconstruction.list` or `reconstruction.manifest`.
4. The worker downloads and probes the video with FFprobe, extracts real JPEG frames with FFmpeg, writes a checksummed `frame-manifest.json`, and runs the actual ODM container.
5. ODM must produce a non-empty GLB/GLTF plus LAS, LAZ, or PLY. The worker copies the produced files, computes SHA-256 checksums, writes `reconstruction-metadata.json`, and records provenance and processing metrics in the database manifest.
6. The quality gate rejects missing mesh or point-cloud outputs. Without independent checkpoints/GCPs, the honest result is `review_required`, not a claim of one-metre accuracy.
7. The existing viewer must load the artifact URL from the stored manifest. The backend serves that URL from the same shared artifact directory; no pre-built or synthetic GLB is used.

With no `DRIFT_DETECTION_COMMAND`, detection status is `not_configured` and detection count is zero. The worker never creates fake detections. If a real adapter is configured, it must read `DRIFT_FRAME_MANIFEST` and write a JSON array to `DRIFT_DETECTION_OUTPUT`; records without a world position remain `frame_only_uncertain`.

## Configuration

| Variable | Required | Meaning |
|---|---:|---|
| `DATABASE_URL` | Yes for host backend | PostgreSQL connection used by the application. Compose derives the worker connection from the PostgreSQL service variables. |
| `RECONSTRUCTION_ARTIFACT_HOST_ROOT` | Yes | Absolute host directory shared by the worker and backend. |
| `RECONSTRUCTION_WORK_HOST_ROOT` | Yes | Absolute host directory shared by the worker container and host Docker daemon for ODM project inputs and outputs. |
| `RECONSTRUCTION_WORK_ROOT` | No | Worker-container path corresponding to the host work directory; defaults to `/var/lib/drift/work`. |
| `RECONSTRUCTION_ARTIFACT_ROOT` | Yes for host backend | Backend path to the same directory; defaults to `/var/lib/drift/reconstruction` in the worker container. |
| `ODM_IMAGE` | No | ODM image, default `opendronemap/odm:latest`. |
| `ODM_MAX_CONCURRENCY` | No | ODM concurrency, default `4`. Reduce for constrained hosts. |
| `RECONSTRUCTION_MAX_FRAMES` | No | Maximum sampling budget, default `900`. |
| `RECONSTRUCTION_ODM_TIMEOUT_SECONDS` | No | ODM timeout, default `5400`. |
| `DRIFT_DETECTION_COMMAND` | No | Real detector adapter; unset means zero detections. |

## Honest failure behavior

Missing HTTPS source media, FFmpeg probe failure, fewer than twenty extracted frames, Docker/ODM failure, missing output formats, checksum failures, and database errors mark the job `failed`. No synthetic world, hardcoded GLB, or placeholder artifacts are published. Dynamic-object removal is not claimed unless a configured reconstruction/detection model actually performs it.

## Troubleshooting and cleanup

Inspect worker logs with `docker compose --env-file reconstruction-worker/.env -f reconstruction-worker/docker-compose.yml logs -f drift-reconstruction-worker`. Verify the source URL from inside the worker network, verify that Docker can pull the ODM image, and check available disk before retrying. Stop the stack with `docker compose ... down`; add `--volumes` only when intentionally deleting the local PostgreSQL database and artifact state.
